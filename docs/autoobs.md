# Автообсерв

Модуль выбирает, кого показывать, по каждому пакету GSI (~100 мс) и переключает камеру нажатием цифры 1–0 через агента на ПК с CS2. Пролётки в фризтайм — следующий этап, здесь описан только их план.

## Структура

```
server/autoobs/
  index.js      сборка: вкл/выкл, пауза при ручном управлении, журнал, агенты (Socket.IO /agent), API
  config.js     пороги и времена: autoobs.json с горячей перезагрузкой
  signals.js    сигналы по разнице снимков: стрельба, урон, килл, смерть, кто кого убил, скорость
  director.js   уровни P0–P4, кластеры контактов, правила удержания → решение
  switcher.js   способ переключения: "keys" (агент жмёт цифры), заготовка "console"
  recorder.js   запись потока GSI в recordings/*.jsonl
  spawns.js     спавны карт по позициям игроков во фризтайм → spawns.json
  flyover.js    пути пролёток, кадры spec_goto, планировщик фризтайма
tools/
  autoobs-agent.ps1 / .cmd   агент на ПК с CS2: нажатия, хоткеи, ручной перехват
  autoobs-replay.js          прогон записи GSI без игры
  autoobs-check.cfg          проверка консольных команд в CS2 (шаг 1 ТЗ)
  autoobs_frame.cfg          файл для проверки exec
```

Поток данных: GSI → `server.js` → `autoobs.onState()` → `signals.update()` → `director.decide()` → `switcher.switchTo()` → событие `agent:press` → агент → SendInput (скан-код).

## Конфиг `autoobs.json`

Создаётся рядом с `settings.json` при первом запуске. В файле можно оставить только то, что меняешь: остальное берётся из значений по умолчанию (`server/autoobs/config.js`). Правки подхватываются за 2 с; редактировать можно и в админке.

| Ключ | По умолчанию | Что делает |
|---|---|---|
| `contact.r_contact` | 1500 | враги ближе — возможный контакт (2D) |
| `contact.r_support` | 800 | союзники ближе к участнику — тоже в кластере |
| `contact.big_cluster` | 4 | от стольких игроков контакт крупный (P1) |
| `contact.look_deg` / `look_deg_sniper` | 30 / 15 | «смотрит на врага» |
| `contact.floor_dz` | 200 | \|Δz\| больше — другой этаж |
| `contact.active_window_ms` | 2000 | окно активности контакта |
| `sniper.enabled` / `include_ssg` | true / false | снайперские дуэли, SSG 08 |
| `sniper.max_dist` | 4000 | дальность дуэли |
| `sniper.prefer` | "peeker" | "peeker" — кто выглядывает, "holder" — кто держит угол |
| `quiet.max_enemy_dist` | 3500 | дальше от врага — в тишине не показываем |
| `quiet.approach_weight` | 1.5 | вес сближения в тишине |
| `quiet.bomb_carrier_bonus` | 400 | бонус носителю бомбы за T |
| `timing.min_hold_ms` | 3000 | минимум на игроке |
| `timing.fight_hold_ms` | 1500 | стрелял/получал урон — не уводим |
| `timing.kill_hold_ms` | 1500 | после килла держим |
| `timing.death_switch_ms` | 700 | после смерти текущего |
| `timing.better_ratio` | 1.25 | внутри уровня — только если лучше на 25% |
| `timing.manual_pause_ms` | 5000 | пауза после ручного управления |
| `timing.pre_round_switch_ms` | 1500 | за столько до конца фризтайма — на игрока |
| `timing.kill_attrib_ms` | 300 | окно сопоставления убийцы и жертвы |
| `switch.method` | "keys" | способ переключения |
| `log.file` | "autoobs.log" | журнал решений (пусто — не писать) |

## Приоритеты и правила

- **P0 клатч** 1 против 2+: сразу на одиночку и до конца раунда. 1 на 1 — кто ближе к действию, переключение только при явной причине (бомба, бой).
- **P1** кластер от `big_cluster` игроков или AWP-дуэль. **P2** — кластер меньше. Кластер: враги ближе `r_contact` на одном этаже, и хотя бы один смотрит на другого или есть стрельба/урон; плюс союзники в `r_support`. Из нескольких — самый активный (игроки + выстрелы + попадания за 2 с). Внутри: стреляющий → получающий урон → смотрит на врага и ближе всех → заходит первым.
- **P3** закладка/дефьюз, если нет контактов. **P4** тишина — ближе всех к врагу с учётом сближения.
- Удержание: минимум `min_hold_ms` (кроме более высокого уровня, смерти текущего, клатча); с перестрелки не уводим даже ради P1 (кроме клатча); после килла держим; убили текущего — через `death_switch_ms` на убийцу, если он в бою.
- Без переключений: конец раунда, тайм-ауты, разминка, перерыв. Фризтайм — за `pre_round_switch_ms` до старта камера на игрока (пока нет пролёток).

## Агент

Запуск на ПК с CS2: `tools/autoobs-agent.cmd` (в нём адрес сервера; на одном ПК — `http://localhost:3000`).

- Протокол — Socket.IO, пространство имён `/agent` (агент не получает пакеты HUD).
  - агент → сервер: `agent:hello`, `agent:hotkey {action:"on"|"off"}`, `agent:manual {reason}`, `agent:focus {cs2}`, `agent:pressed {seq,key,skipped?}`
  - сервер → агент: `agent:press {seq,key,ttl_ms}`, `agent:release_all`, `agent:state {enabled,paused}`
- Хоткеи (в окне CS2; ключ `-HotkeysAnywhere` — везде): Ctrl+Shift+PageUp — включить / снять паузу, Ctrl+Shift+PageDown — выключить и отпустить все клавиши агента. Проверь, что в CS2 эти сочетания ни на что не забиндены.
- Ручное управление в окне CS2 (цифры, кнопки мыши, движение мыши) — пауза на `manual_pause_ms`, потом автомат возвращается сам. Свои нажатия агент отличает по флагу injected.
- Чувствительность к мыши: `-MouseMoveEvents 25` (столько событий за 400 мс).

## Отладка

- Админка → «Автообсерв»: ВКЛ/ВЫКЛ, пауза, агент и фокус CS2, текущий уровень, контакты с очками, кандидаты тишины, таймеры удержания, журнал, запись GSI, редактор конфига.
- Журнал решений — `autoobs.log`: `P0 CLUTCH 1v3 → nick (слот 4)`, `P1 CONTACT 3T v 2CT → nick (слот 2)`, `DEATH → убийца nick`.
- Запись: «Записывать» в админке → `recordings/gsi-*.jsonl`. Прогон без игры:
  `node tools/autoobs-replay.js recordings/<файл>.jsonl --why` (ключи: `--config <файл>`, `--recorded`).
- Демки: при просмотре демки GSI тоже отдаёт данные — можно записывать и прогонять.

## Известные ограничения

- **Стрельба** считается по `ammo_clip` в `allplayers_weapons`. В HUD есть пометка, что у зрителя `ammo_clip` в allplayers может не приходить. Тогда сигнал стрельбы есть только у игрока на камере, остальное — по урону. Проверить по записи GSI.
- **Линия видимости** GSI не даёт: стена между игроками не учитывается, только этажи по Δz и направление взгляда.
- Регламент 24 раунда (MR12).

## Шаг 1 ТЗ: что проверить в CS2

Скопируй `tools/autoobs-check.cfg` и `tools/autoobs_frame.cfg` в `game/csgo/cfg/`, зайди зрителем и выполни в консоли `exec autoobs-check`. Пришли `game/csgo/autoobs_check.log` (или скриншот консоли).

| Что | Как проверить | Зачем |
|---|---|---|
| `find spec_` | в cfg | какие spec_-команды доступны зрителю |
| `spec_goto x y z pitch yaw` | вручную в свободной камере | телепорт камеры для пролёток (вариант 2 и 4) |
| `spec_pos`, `getpos` | в cfg | снятие координат для записи путей |
| `con_logfile`, `-condebug` | cfg пишет лог; `-condebug` — параметр запуска, файл `console.log` | чтение координат агентом |
| `+left` / `+right`, `cl_yawspeed` | в cfg (`find`) и вручную в свободной камере | орбита на зажатых клавишах (вариант 3) |
| exec из бинда | `bind <клавиша> "exec autoobs_frame"` и нажать: в консоли `AUTOOBS FRAME OK` | «exec-трюк» для spec_goto 30+ раз в секунду |
| свободная камера | `spec_mode` и переход в roaming на сервере | без неё пролёток не будет |

Выводы по этой таблице определят способ воспроизведения пролёток (порядок вариантов — как в ТЗ).

### Результаты первой проверки (2026-10-26)

| Что | Результат |
|---|---|
| `spec_goto` | есть, флаги `client clientcmd_can_execute`, не cheat |
| `spec_pos` | работает, но помечен `cheat` (на матч-сервере без sv_cheats может не работать) |
| `getpos` | вывел `setpos …;setang …` |
| `spec_lerp` / встроенный плавный пролёт | нет |
| `+left` / `+right` / `cl_yawspeed` | нет (`no results`) → вариант 3 невозможен |
| `exec autoobs_frame` | работает (`AUTOOBS FRAME OK`) |
| `con_logfile` | не выводит значение → похоже, нет; проверить `-condebug` |
| `spec_usenumberkeys_nobinds` | `true` — цифры у зрителя работают напрямую |
| `spec_autodirector` | есть встроенный автодиректор (держать выключенным, чтобы не спорил с нашим) |
| `spec_player` | «по имени или слоту», `clientcmd_can_execute` — кандидат для консольного способа |

Решение: вариант 2 — `spec_goto` по шагам через exec-трюк; запасной — вариант 4 (статичные планы).
Осталось проверить плавность: `autoobs-agent.ps1 -FlyTest` (см. ниже).

### Тест плавности облёта

1. В консоли CS2 один раз: `bind "kp_minus" "exec autoobs_frame"`.
2. Зайти зрителем, перейти в свободную камеру, взять центр из `getpos` / `spec_pos`.
3. Запустить:
   `powershell -ExecutionPolicy Bypass -File tools\autoobs-agent.ps1 -FlyTest -CfgDir "<…>\game\csgo\cfg" -Center "334 2433 -56" -Hz 60`
4. Переключиться в CS2 — облёт начнётся через 1,5 с, 12 с по орбите. Попробовать `-Hz 30` и `-Hz 64`.
   Ключи: `-Radius 600 -Height 400 -Speed 150 -Seconds 12 -FrameKey kp_minus|kp_plus|kp_multiply`.

Что смотреть: плавно ли движется камера, нет ли рывков; меняется ли позиция вообще (если стоит на месте — CS2 кэширует cfg и exec-трюк не работает).

Позиция камеры из GSI: в `player_position` (добавлено в конфиг GSI) в свободной камере может приходить позиция самой камеры — смотри строку «Камера (GSI)» на отладочной странице. Если приходит, запись путей пойдёт без консоли и без `spec_pos`.

## Пролётки в фризтайм

Модули: `server/autoobs/spawns.js` (спавны), `server/autoobs/flyover.js` (пути, кадры, планировщик).

**Спавны** берутся не из интернета, а из GSI: во фризтайм игроки заморожены на точках спавна, и сервер запоминает их позиции по карте и стороне в `spawns.json`. Достаточно одного фризтайма на карте; после патчей карт спавны обновятся сами (или «Сбросить спавны карты» в админке).

**Пути** по спавну, три варианта:
- `orbit` — дуга −55°…+55° перед игроками, камера смотрит в центр спавна;
- `dolly` — проход вдоль строя перед игроками, взгляд скользит следом;
- `crane` — издалека и пониже — ближе и выше, наклон вниз растёт.

«Перед игроками» — в сторону спавна врага (там открытое пространство, сзади обычно стена). Высота — `flyover.height` (450) над спавном. Записанные пути из `flyovers.json` (формат ТЗ) для карты/стороны заменяют сгенерированные.

**Кадры**: позиция — Catmull-Rom с равномерной скоростью по длине пути, взгляд — на сглаженную точку (записанные: углы с учётом перехода через 360°). Скорость — трапеция с плавным разгоном/торможением; длительность 8–15 с из длины пути (`speed`) и поворота (`max_turn_dps`). Короткий фризтайм — обрезка с плавным торможением до нуля. Сервер считает кадры `spec_goto` с частотой `hz` и отправляет агенту (`agent:fly`), агент проигрывает их через exec-трюк.

**Когда**: только при включённом автообсерве, в фризтайм, старт через `start_delay_ms`, конец за `end_before_ms` до конца фризтайма; если до конца меньше `min_freeze_ms` — не запускается; не в разминке; в тайм-аутах — по `in_timeouts`. После пролётки — нажатием цифры на игрока по правилу P4.

**Над каким спавном**: команда, выигравшая прошлый раунд (`round.win_team`, запасной — `map.round_wins`), по составу игроков — поэтому после смены сторон берётся спавн, где она играет сейчас. Первый раунд — случайный. Вариант не повторяется подряд для того же спавна.

**Прерывание**: конец фризтайма, выключение (Ctrl+Shift+PageDown), ручное управление в окне CS2, потеря фокуса CS2 — агент сразу останавливает пролётку и отпускает клавиши. События для HUD: `flyover:start`, `flyover:end`.

**Предпросмотр и запись** — в админке, панель «Пролётки в фризтайм»: кнопки ▶ по каждому варианту (работает без матча, если спавны карты уже выучены), «Стоп», запись своей пролётки по точкам камеры из GSI → `flyovers.json`.

**Агенту нужно**: бинд `bind "kp_minus" "exec autoobs_frame"` и папка cfg (`-CfgDir`, по умолчанию стандартный путь Steam).

Проверить в CS2:
- работает ли `spec_goto` из вида от первого лица или сначала нужна свободная камера — если нужна, найти номер режима (`spec_mode 4` / `spec_mode 6`) и вписать в `flyover.enter_cmd`;
- возвращает ли нажатие цифры после пролётки к виду от первого лица — если нет, вписать нужный `spec_mode` в `flyover.exit_cmd`;
- не прорезает ли камера крыши на конкретных картах — тогда уменьшить `flyover.height` или записать свою пролётку.
